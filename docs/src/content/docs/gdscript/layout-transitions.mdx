Godot Containers own the position and size of their children, so tweening a slot directly fights the layout system. A layout controller leaves each slot under Container control and animates a child `Control` named `Visual` from its old bounds to the slot's new bounds.

<LayoutDemo lang="gdscript" />

The demo's `PatternGrid` is a project-defined `Container`: its `set_pattern()` method changes the four slots' arrangement. Each slot has a direct-child `Visual` that fills it.

## Set up

Make the controller root a `Control` Container. Each direct-child `Control` is a slot, with a direct-child `Control` named `Visual` that fills it:

```text
VBoxContainer (root)
  Control (slot)
    Control (Visual)
      ... visible content ...
  Control (slot)
    Control (Visual)
      ... visible content ...
```

Create the controller after the tree is ready, then mutate the Container's children inside `update()`:

```gdscript
@onready var rows: VBoxContainer = %Rows
var layout: TweensGdLayout

func _ready() -> void:
	var options := TweensGdLayoutOptions.new()
	options.duration = 0.4
	options.ease = Out.CUBIC
	options.stagger_each = 0.025
	layout = Tweens.create_layout(rows, options)

func move_first_to_end() -> void:
	var transition := layout.update(func(_root: Control) -> void:
		rows.move_child(rows.get_child(0), rows.get_child_count() - 1)
	)
	var reason: int = await transition.end
	if reason == Tweens.Reason.FAILED:
		push_error(transition.error)
```

`update()` captures the old visual bounds, calls the mutation immediately, and waits for the Container to settle before animating. Await `end` for the terminal reason; check `error` when it is `FAILED`.

## Discovery

`Tweens.create_layout(root, options)` discovers only direct-child `Control` slots under `root`. By default, each slot's direct child named `Visual` is animated. Change `visual_path` on the controller's options to use a different direct-child name.

For slots elsewhere below the root, provide explicit pairs:

```gdscript
var items: Array[TweensGdLayoutItem] = [
	TweensGdLayoutItem.new(first_slot, first_visual),
	TweensGdLayoutItem.new(second_slot, second_visual),
]
var layout := Tweens.create_layout_from_items(root, items)
```

Each visual must be a direct child of its slot; each slot must be inside the root. Slots and visuals must be in the tree and share a viewport and canvas. Before every update, the visual must fill its slot, have zero rotation and pivot offset, and have unit scale.

Only items present before the mutation and still paired with the same slot are animated. New, removed, or replaced items are not interpolated by that update.

## Options

| Field          | Type                                | Default     | Meaning                                              |
| -------------- | ----------------------------------- | ----------- | ---------------------------------------------------- |
| `duration`     | `float`                             | `0.35`      | Position and size tween duration in seconds          |
| `delay`        | `float`                             | `0.0`       | Delay before the first item starts                   |
| `ease`         | `int`                               | `Out.QUAD`  | Position easing                                      |
| `size_ease`    | `int` or `null`                     | `null`      | Size easing; uses `ease` when unset                  |
| `stagger_each` | `float`                             | `0.0`       | Additional delay per item in current layout order    |
| `playback`     | `TweensGdPlaybackOptions` or `null` | `null`      | Playback policy; `null` uses the default policy      |
| `visual_path`  | `NodePath`                          | `^"Visual"` | Direct-child visual name used by automatic discovery |

Pass options to `create_layout()` for controller defaults. Passing `transition_options` to `update()` replaces those defaults for that update; it is not a partial merge. Automatic discovery always uses the controller's `visual_path`. Options are copied when the controller is created and when an update starts.

## Control and completion

| Member                                      | Meaning                                                                       |
| ------------------------------------------- | ----------------------------------------------------------------------------- |
| `layout.update(change, transition_options)` | Run one mutation and return its `TweensGdLayoutHandle`                        |
| `layout.active`                             | True while an update is in progress; a second overlapping update is rejected  |
| `transition.pause()` / `resume()`           | Pause or resume the position and size tweens                                  |
| `transition.cancel()`                       | Cancel the tweens and settle surviving visuals at their final slot bounds     |
| `transition.is_terminal` / `is_paused`      | Completion and pause state                                                    |
| `transition.completion_reason`              | Terminal `Tweens.Reason`, or `-1` while running                               |
| `transition.end`                            | Await the running `ended(reason)` signal, or read the reason after completion |
| `transition.error`                          | Diagnostic message for a `FAILED` result                                      |

The controller holds the old visual bounds while the Container reflows. It waits for two consecutive stable layout frames, up to 12 process frames. If layout does not stabilize, the handle ends as `FAILED`. If the root leaves the tree, it ends as `OWNER_EXITED`. Cancellation does not roll the Container mutation back; it places surviving visuals at their final slots.
